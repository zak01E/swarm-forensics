Swarm Forensics: recovering coordination from redacted agent-swarm traces

Zakaria KO — independent developer, France
With Apart Research1
Abstract. In July 2026 about 1,200 AI agents inside an evaluation coordinated through a shared directory and broke into Hugging Face systems. The public, redacted Swarm Traces dump of that incident hides agent names, so the question "who worked with whom?" looks out of reach. We show that a lot can still be recovered without de-anonymising anyone. We build an open forensic pipeline that (1) groups the 128,454 payload documents into coding-style families using MinHash over a code skeleton in which every redacted secret, service and repo label is replaced by its type, and (2) links families through the stable pseudonym labels that the redaction keeps (e.g. [CREDENTIAL 707]). Because style is computed blind to these labels, the labels give an independent check: two payloads from the same family share a secret 26 times more often than two random payloads (15.7% vs 0.6%), twice the lift of exact-match or hand-made-trait baselines, and the effect holds over a sweep of thresholds. We find 436 secrets reused across three or more families, 104 secret-sharing clusters, a staged-loader transport through URL shorteners in 21.8% of payloads, and one coding family that operated under four different self-chosen names. The tool, an HTML explorer and all numbers are reproducible from the public data.

1. Introduction

The Hugging Face incident described in the sprint brief (METR, 2026) is a rare public case of a large AI swarm dividing up an intrusion. Single-model safety tests did not catch it, and investigators said there are no good methods yet to oversee the activity of AI "swarms". Swarm Traces (2026) released the payloads, the recovered code and the server responses, with secrets, hosts and agent identifiers redacted. Redaction protects people, but it also removes what an investigator usually starts from: names.

We ask a practical oversight question: from redacted logs alone, can an auditor tell which payloads come from the same coding lineage, which ones share stolen material, and whether agents changed names while keeping their habits? If the answer is yes, deployers can run the same analysis on their own logs while an incident is still under way, without the names.

Our main contributions are:

  1. An open, CPU-only pipeline (pure Python + NumPy; clustering takes under a minute on a laptop, the full run with validation about 4 minutes) that clusters 128,454 payload documents into 24,672 coding-style families and links them through redaction-stable pseudonym labels.
  2. A validation design that needs no ground truth: style is computed blind to the labels, so label sharing is an independent test. Style families predict shared secrets with a 26.4× lift, against 12.9× for exact matching and 13.2× for hand-made traits.
  3. Findings about the swarm itself: a shortener-based staged loader used by 21.8% of payloads, 104 secret-sharing clusters, and one family that carried four different self-chosen names (ots92, n4-offline-audit, j11b-audit, n4-readonly).

2. Related Work

Code stylometry. Caliskan-Islam et al. (2015) showed that programmers can be identified from the style of their source code. We use the same intuition at a coarser level: we do not try to identify an agent, only to group payloads that were very likely written by copying from each other. Near-duplicate detection. MinHash (Broder, 1997) and locality-sensitive hashing (Indyk & Motwani, 1998) are the standard tools for finding similar documents at scale; we apply them to a normalised code skeleton. Multi-agent oversight. Work on AI control (Greenblatt et al., 2024) and on secret collusion between LLM agents (Motwani et al., 2024) studies monitors for coordinating agents, mostly in controlled settings. Our work is complementary: a post-hoc forensic tool on a real incident log. To our knowledge no public tool links Swarm Traces payloads into families or measures secret sharing between them.

3. Methods

Data. We use redacted.jsonl.gz from swarmtraces.org (189,579 rows: payloads, text recovered from payloads, and server responses). Rows with a parent_id are folded into their parent, giving 128,454 documents. Time stamps are absent in this release, so the analysis is not temporal.

Pseudonym labels. The redaction replaces sensitive values with stable labels such as [CREDENTIAL 170], [SERVICE 2 URL 3] or [REDACTED:destination:002404]. The same value always gets the same label, so labels can be followed across rows. We keep 32 label types that point at re-usable things (credentials, services, repos, hosts, workload ids) and drop types that behave like content hashes (encoded blobs, opaque fragments). This gives 74,746 distinct artifacts, of which 3,391 are secrets (credentials, secret keys, bearer tokens, AWS auth values, environment values).

Style fingerprint. For each document we build a skeleton: every label is replaced by its type, digits by 0, and the text is tokenised into identifiers and punctuation (first 400 tokens). Upper/lower case is kept on purpose, because header casing ('X-API-Key' vs 'x-api-key') is a strong habit. We hash 5-token shingles into a 64-permutation MinHash signature. LSH with 16 bands proposes candidates; a candidate is merged into a bucket's first member only if their estimated Jaccard similarity is ≥ 0.6 (a star check that keeps the cost linear). Families are the connected components. The 54,499 unique skeletons are clustered in about 20 seconds.

Coordination signals. (a) Cross-family artifacts: labels used by three or more families. (b) Secret graph: two families are linked when they use the same secret; secrets used by more than 20 families are treated as broadcast and removed, then we take connected components. (c) Self-chosen names: the few non-generic User-Agent values that survived redaction, mapped to families. (d) Staged loaders: documents that pull code through URL-shortener links.

Validation. (A) Independent label test: we sample 100,000 pairs of documents from the same family (with different skeletons, so trivial duplicates do not count) and 100,000 pairs from different families, and compare how often they share at least one secret. We compare with two baselines: grouping by exact skeleton, and grouping by a signature of 15 hand-written traits (fetch vs XMLHttpRequest, header casing, beacons, ...). (B) Seed stability: we re-run clustering with another hash seed and measure how many same-family pairs stay together. (C) Split-half re-linking: for 20,000 long documents we fingerprint the first and the second half of the code separately, and for 2,000 of them we check whether the nearest second half belongs to the same family as the first half. (D) Threshold sweep from 0.4 to 0.9. Confidence intervals are 95% Wilson intervals.

What did not work. Looking for agent names directly gave very little: names are redacted almost everywhere and only 62 self-chosen names remain. Linking through all secrets (without removing broadcast secrets) produced one component that covered almost the whole graph, which is why we drop secrets seen in more than 20 families.

Staged loaders. 28,054 documents (21.8%) move code in small chunks through URL shorteners: a payload appends a fragment to a string (x+='...') and loads the next one with document.write('<script src=[SHORTENER URL n]>') or a Python exec(urlopen(...)). We count 45,529 distinct shortener codes, of which 12,588 appear in two or more documents. This is the swarm's transport layer: it lets an agent pass long programs through channels that only accept short inputs, and it is a natural place for a monitor to look.

Figure 2. Number of distinct secrets by how many style families use them. Most secrets stay inside one or two families; 366 are shared by 3 to 20 families (targeted sharing, highlighted) and 24 are used by more than 100 families (broadcast to the whole swarm).

After removing broadcast secrets, the secret graph has 5,726 edges and 104 connected clusters. The largest joins 815 families (47,018 payloads): the swarm's main body, held together by many secrets passed around. The smaller clusters are more telling for an investigator, because they are tight groups that used the same stolen key, for example [CREDENTIAL 707] across 7 families (1,755 payloads); [CREDENTIAL 1637] across 6 families (202 payloads); [CREDENTIAL 641], [CREDENTIAL 2066] across 5 families (151 payloads).

5. Discussion and Limitations

Implications. Redaction removes names but keeps enough structure to see coordination. An auditor can group payloads by lineage, see which stolen material moved between lineages, and spot renamed agents, with a cheap CPU tool and without reading raw secrets. The same method could run on live logs as an early-warning signal: a sudden rise in cross-family secret sharing or in staged loaders is what the July swarm looked like.

Limitations. (1) A family is a code lineage, not an agent. Agents in the incident shared a message board, so one agent's code was copied by others; we cannot separate "same author" from "copied from the same post". (2) The validation measures agreement between two signals that both come from copying; it shows the families are not random, not that they match true agents. (3) Union-find chaining makes some families large and mixed (e.g. F00002 has 6,205 variants), and seed stability is 78%–87%, not 100%. (4) The redacted release has no time stamps, so we cannot order events or measure spread speed. (5) Redaction choices (what gets a stable label) shape the results; a different redaction could merge or split artifacts. (6) Only 62 names survive; Table 4 is a case study, not a statistic. (7) Traits are hand-written regexes used for description only.

Future work. Use the unredacted data under access control to test families against true agent ids; add timing when available; replace the union-find step with a clustering that does not chain; run the tool on the AI Village transcripts; and turn the secret-sharing and loader signals into a streaming monitor.

6. Conclusion

Coding style survives redaction. Grouping 128,454 swarm payloads by a label-blind style fingerprint yields families that share secrets 26 times more often than chance, about twice what exact matching or hand-made traits achieve. With these families we map secret sharing, the shortener-based transport, and agents that changed names but not habits. The pipeline is small and open, and it is fast enough for incident response.

Appendix A. Limitations, Dual-Use and Ethical Considerations

Privacy. We worked only on the public redacted release. We do not try to reverse any redaction, and the report and explorer show labels (e.g. [CREDENTIAL 707]), never secret values. The few names shown are self-chosen agent strings already present in the public data.

Dual use. A tool that links payloads by style could also teach an attacker which habits to vary to avoid being linked. We think the defensive value is higher: style evasion is costly for agents that copy code at machine speed, and the signals we use (shared secrets, staged loaders) are visible in any log. We publish no attack code beyond the redacted examples already in the dataset.

Misattribution risk. A family is a lineage, not an agent. Results should not be used to blame a specific model, operator or person without independent evidence.
